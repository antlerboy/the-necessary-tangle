Specify the states, probabilities, and task

These four states are invented. At the default, A has probability 97%, and B, C, and D each have 1%. The task requires the same ‘routine’ action for A and B, a callback for C, and partner coordination for D. These are labels in a finite example, with no claim about a real service.

The three share this probability equally; A receives the remainder.

The poor and default-task groupings are alternative coarsenings of the full-state map. Neither refines the other. Their entropy comparison therefore does not describe a further compression from one to the other.

Best expected correctness weights the stipulated probabilities and assigns the same cost to every wrong action. It is not equal weighting of the four states or a measured algorithm accuracy. When actions tie, this example chooses the first encountered in state order A, B, C, D. At the default, ‘other’ is therefore decoded as ‘routine’, missing C and D; other equally optimal tie choices miss different states. Unequal consequences require a separate loss model.

The functional test

g = h ∘ f exactly when f(x₁) = f(x₂) implies g(x₁) = g(x₂).

Here f is the classification, g is the required action, and h is a rule that receives only the classification. Check every pair in each label group. If one group contains incompatible required actions, no such rule can be right for every member. This is a statement about the specified task; it does not decide which task ought to be chosen.

This criterion, the invented example, and its interpretation are new mathematical/editorial exposition. The primary sources below support the stated information measures and accounting distinctions.
