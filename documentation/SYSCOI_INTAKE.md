# Automatic public SysCoI resource intake

## Scope and visible result

The existing hourly publication worker owns this intake. There is no separate collector or new schedule. It observes public posts on WordPress site `130780538`, `https://stream.syscoi.com/`, and maintains `sources/syscoi/intake.json` in `antlerboy/the-necessary-tangle` on `main`.

The deterministic final build overlay publishes the resources at `https://transduction.systems/library/syscoi/`, with a stable `#post-<WordPress ID>` anchor for every observation. Its JSON download is `/library/syscoi/intake.json`. New resources also appear in the searchable source register at `/library/`, under the `SysCoI reading` collection. An existing catalogue record is reused when the same primary URL is already present; the new public post is attached as provenance. A source-register link points to the dedicated collection.

The overlay adds `src_syscoi_post_<ID>` source records and source-level descriptions. It leaves all graph nodes, profiles, edges, claims, evidence, journeys, canonical redirects, and random-entry eligibility unchanged. A resource can link to an existing atlas entry. Deeper conceptual integration requires located evidence and a separate editorial packet; no placeholder essay or invented influence claim is produced by ingestion.

The initial reconciliation covers the six public posts found after the 24 October 2026 intake through the check on 7 November. O’Rourke reuses `cybernetic_reading_orourke`, `src_syscoi_post_29183`, and `publication_syscoi_post_29183`. Five further resources enter the source register. Ludos retains its verified public title/link and precise HTTP 403 access limitation. Other descriptions cite the primary page or the publisher’s own announcement and state any reading limits.

## Writer procedure

1. Read the latest repository `main` SHA, manifest, and this guide. Read WordPress public posts (`status=publish`), excluding password-protected posts. The 24 October 2026 publication cutoff applies only to the initial catch-up. On subsequent runs enumerate public posts ordered by `modified` descending, without a publication-date `after` filter, and paginate through the previous successful modified-time watermark plus an overlap. This includes genuinely new publications with an older/backdated publication date, even before 24 October. Also reconcile recently published public IDs and unresolved/retry records; never advance a watermark past a failed page. Periodically reconcile the full public-ID set so a change in timestamps cannot permanently hide a publication.
   At activation, retain the observation time and the public IDs/modified values already present in the overlap as an activation baseline in the existing ledger. The six seeded rows are the authorised initial catch-up. Full-ID reconciliation is a gap check, not permission to bulk-import untouched historical posts: add only genuinely new or changed publications after activation, those seed rows, or separately authorised reconciliation. An old post absent from this manifest is not automatically a new publication. Unchanged historical overlap rows remain baseline observations; they do not create TNT resources or social backfill.
2. For every new or changed public post, read its current rendered content. Preserve its ID, published GMT time, site-local modified timestamp, SHA-256 of the exact UTF-8 rendered content returned by WordPress, author attribution, observed URL, and outbound URLs. Never convert a draft into a resource, publish a WordPress draft, or use private content. Detect a previously ingested post becoming private/deleted and stop exposing private text; retain an appropriately minimal withdrawn provenance tombstone through a separately reviewed removal rather than republishing cached private material.
3. Check the earlier source register and graph before assigning an existing identity. Match the canonical primary resource URL, a verified alias, or an explicit bibliographic identity. The builder searches all existing sources and the entire library catalogue, and resolves existing node redirects. An `original_urls` match establishes identity automatically only for an explicitly labelled discovery-provenance record with one unique outbound destination; other outbound matches remain candidates. If several existing identities match, the writer must verify and provide `canonical_resource_id`, or the builder retains a separate resource with `identity_status: ambiguous_existing_matches` and recorded `match_candidates`. It never picks a lexicographic winner among ambiguous identities. Incidental citations and concepts that cite a work are not resource identities. Title resemblance alone does not establish identity. Distinct editions or substantive revisions must be distinguished or attached as versions, with the basis recorded.
4. Write a useful, attributed description from the published post and, for a link-only post, the original public destination. Preserve the user’s substantive description where it is their writing. Attribute third-party claims and respect source quotation limits; do not copy full articles or publicise private material. Record exact source URLs and page/section locators. If a destination is inaccessible, keep the verified discovery title/link and the precise limitation. Do not invent unseen content. Resource authors are distinct from the SysCoI poster.
5. Merge complete rows by `site_id` plus `post_id`, retaining all other rows, existing fields, and version history. `python3 scripts/merge_syscoi_intake.py /tmp/incoming-public-posts.json` performs the local merge and prints a no-change result when unchanged. An input can be an array of rows or an object with a `posts` array. Do not update timestamps merely because an unchanged poll occurred, and do not commit an unchanged manifest.
6. Run `make validate` for a code change. A routine manifest-only write must run `make apply-syscoi-intake`, `python3 scripts/validate_syscoi_intake.py`, and `python3 scripts/validate_public.py`, then rely on the repository’s full CI gate. Commit the manifest using its current contents SHA, or create a commit based on the observed main SHA and update the ref with `expected_sha`. On conflict, reread current main, merge the intended rows again, and revalidate. Never replace another writer’s newer manifest wholesale. GitHub app/connector commits use the existing Pages push workflow; do not add a competing schedule.
7. A successful commit is not a publication receipt. Observe the Publish workflow for that commit, then read the live `/deployment.json` and `/library/syscoi/intake.json`. Verify the expected `post_id`, `content_sha256`, `resource_id`, and manifest hash. Only then record TNT complete in the existing publication ledger. Store the commit/run/live URLs, and retry only unfinished destinations after failure. Do not enqueue historical social backfill as a side effect of this TNT catch-up.

The hourly worker’s enabled state and successful execution must also be monitored. This repository does not make a paused or failed automation run. An end-to-end unattended run is a separate operational check from a successful build and deployment.

## Manifest contract

Top-level fields are `schema_version: 1`, `site_id: 130780538`, `site_url`, `initial_publication_cutoff`, and `posts`.

Each post row contains:

- `post_id` (integer), `post_url`, and decoded plain-text `title`.
- `status: "publish"` and `password_protected: false`, verified from the current WordPress read.
- `published_gmt` (ISO timestamp with `Z`), `modified_local` (the exact site-local WordPress timestamp), `content_sha256` (64 lowercase hex characters), `author_id`, and public `author_name`.
- `primary_url`, `original_urls` (observed outbound URLs, including original tracking forms), and `canonical_aliases` (only verified same-resource aliases). The comparison key removes `www.`, a trailing slash, fragments, and known tracking parameters, and normalises the scheme. It retains meaningful query parameters. Original URLs remain in provenance.
- Optional `canonical_resource_id`, naming an actually matched catalogue, source, or canonical atlas node ID. An unsupported ID fails validation. Leave this out for new resources.
- `source_authors`, `description`, and `description_status` (`source_scoped_summary` or `link_only_access_limited`). The latter explicitly distinguishes a retained link from a description of material that has been read.
- `description_sources`: objects with a public `url`, a specific `locator`, and `checked_at` date.
- `versions`: objects with `modified_local`, `content_sha256`, `observed_at`, and, where available, the observed `post_url` and `original_urls`. Preserve earlier observations when the current post changes. The current modified/hash pair must occur exactly once.

Use the six real rows in the manifest as examples. The source projection is additive: earlier curated source rows retain their existing fields; new continuously maintained provenance rows can be updated in place under their stable IDs. Each public output post records its canonical resource resolution, existing source/node/catalogue IDs, and current hash. No-op runs preserve identical generated data.

## Build and verification

`scripts/build_syscoi_intake.py` runs last in `make build`, and after the historical 0.41 validator in `make validate`. Historical release gates keep their original counts; the current public source counts then reflect the intake. It updates the mirrored data files, source-register data, collection page/download, library link, quality snapshot source count, and the standing intake note in `NEXT_WORK.md`.

`scripts/validate_syscoi_intake.py` verifies public-only input, unique post/source/catalogue IDs, O’Rourke’s existing identity, tracking-URL duplicate reconciliation, history-preserving updates, unchanged-run idempotence, retained source rows, unchanged graph fields, live-page anchors, and the downloaded manifest hash. The existing public/reader validators run afterwards. Desktop and narrow-screen checks cover the new collection and library search. The original bottom-right `Open updates` control remains present.
