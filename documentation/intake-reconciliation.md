# Feedback and contribution intake reconciliation

A public release must reconcile three different kinds of input before it can claim to have picked up the current feedback.

1. **Running curator feedback** — rough observations in issue #2.
2. **Site-generated contributions** — structured correction, challenge, source, missing-entry and usability issues created from the website.
3. **Standing research programmes** — larger corpus, lineage, semantics, source and interface issues whose completion tests extend across releases.

These feeds are not substitutes for one another. A successful site submission can otherwise disappear because the running notebook was used as the only release queue. Issue #21, submitted by Ivo Velitchkov through the site, exposed that failure.

## Release rule

Before each release:

- list all open site-generated contribution issues created or changed since the previous release;
- read all new comments in the running-feedback issue;
- review changes to standing research issues;
- record each item as accepted, partly incorporated, deferred with a reason, rejected with a reason, or still under review;
- cite the originating issue or comment in the release ledger;
- do not close a contribution issue until the accepted change is live or a clear curatorial decision has been recorded.

The public forms are an intake mechanism, not an automatic publishing mechanism. The curator remains responsible for evidence, wording, boundaries and release acceptance.
