# Publication risks and controls

The public atlas is useful partly because its statements, sources and editorial choices are inspectable. The same visibility creates risks that must be designed for rather than appended as a disclaimer.

## False authority and reputational overclaim

How it happens: A polished interface can make brief, provisional or collection-derived entries look settled.

Current controls: Visible depth and status labels; source locators; explicit rival accounts; release notes that state what was not done.

## False genealogy

How it happens: Citation, co-presence, chronology, teaching, collaboration and influence can be collapsed into one implied family tree.

Current controls: Typed relations; minimum evidence by relation; disputed and unresolved states; no inferred influence from co-occurrence alone.

## Privacy and confidential-source leakage

How it happens: Private SharePoint, email or client material can enter public data through research notes, URLs, excerpts or generated summaries.

Current controls: Separate private lead logs; public-source replacement; automated private-URL scanning; human review before merge; complete deletion from history when secrets appear.

## Copyright and licence error

How it happens: Open access, public availability and permission to republish are not the same thing.

Current controls: Link and summarise; store bibliographic facts and short evidence summaries; record source terms; do not relicense third-party works.

## Identity collision

How it happens: Initials, alternate names and shared names can merge different people or split one person into several records.

Current controls: Authority identifiers, affiliation and publication checks, canonical redirects, and no interpretive edges before resolution.

## Source monoculture and boundary capture

How it happens: A few corpora define what the atlas notices, making their omissions look like properties of the field.

Current controls: Source-mining register; comparator programme; coverage reporting by tradition and domain; deliberate rival and critical sources.

## Automated feedback loops

How it happens: AI-generated descriptions may be re-ingested, cited or paraphrased until an unsupported statement acquires the appearance of independent repetition.

Current controls: Named human sponsor; provenance to non-generated sources; mark AI assistance; never treat generated text as corroboration.

## Vandalism or premature contributor access

How it happens: A public collaboration request can be mistaken for direct editorial authority.

Current controls: Issues and pull requests by default; branch protection; required validation; curator approval; granular roles only in an organisation account.

## Security and operational disclosure

How it happens: Workflow files, logs, repository history or backups can reveal tokens, internal hostnames and infrastructure detail.

Current controls: Least-privilege tokens; secret scanning; protected environments; encrypted off-platform backups; routine restore tests; no credentials in repository data.

## Public permanence

How it happens: Deletion from the current branch does not guarantee removal from forks, caches, clones or repository history.

Current controls: Assume publication is durable; minimise personal data; use GitHub's sensitive-data removal process promptly when required.
