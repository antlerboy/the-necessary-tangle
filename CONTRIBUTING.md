# Contributing to The Necessary Tangle

Corrections, challenges and additions are part of the project. They do not alter the atlas automatically.

## Choose the right route

Use a GitHub Issue to correct an entry, challenge a connection or statement, suggest a source, propose a missing item, report a usability problem or apply for a project role.

Use GitHub Discussions for open questions, interpretation, wider disagreement and exploratory connections not yet ready to become proposed records.

Use a fork and pull request for an agreed, bounded research, data, documentation or software contribution. Direct write access is not required.

## A useful contribution states

1. the entry, connection or corpus concerned;
2. the smallest precise change or challenge;
3. why it matters;
4. the source;
5. the exact page, section, timestamp, archive reference or other locator where possible;
6. uncertainty, competing accounts and what remains unchecked.

A public URL is preferred. Where no open copy exists, give a complete bibliographic or archive citation and mark it ‘No public link’.

## Agent or LLM assistance

Disclose the tool, what it did and the named human sponsor. The sponsor must check the source support and exact diff. Agent-generated text is a proposal, not evidence, and agents receive no direct push or auto-merge right. See [AGENTS.md](AGENTS.md).

## Curatorial outcomes

A proposal may be accepted, accepted with revised wording or scope, kept visible as disputed, held for more evidence, or declined with a reason. Disagreement is not removed merely because the curator makes a current judgement.

## Do not submit

Do not publish private email, internal company or client documents, personal data that is not legitimately public, credentials, tokens, private URLs or large copyrighted extracts. Summarise the evidential point and cite the source instead.
